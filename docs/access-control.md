# 🌍 Модуль геолокационного ограничения доступа по странам (Country-based Geo-Access Control)

Данный модуль обеспечивает дополнительный контур сетевой безопасности приложения на уровне Express-сервера, позволяя ограничивать доступ пользователей по географическому положению (стране).

Модуль спроектирован независимо и не нарушает текущую авторизацию, парольную защиту, расчеты, визуализацию и бизнес-логику проекта.

---

## 🛠️ Файл конфигурации (`config/access-control.json`)

Все настройки вынесены в отдельный файл конфигурации и могут быть динамически изменены администратором без перезапуска или модификации исходного кода.

### Расположение файла:
`/config/access-control.json`

### Структура файла и значения по умолчанию:
```json
{
  "geoAccess": {
    "enabled": false,
    "allowedCountries": [],
    "unknownCountryPolicy": "allow",
    "logDeniedRequests": true,
    "trustProxyHeaders": false,
    "trustedProxyIps": []
  }
}
```

### Описание параметров:
*   `enabled` (boolean): включает или выключает гео-ограничение.
    *   `false` (**по умолчанию**): фильтр полностью выключен, доступ разрешен всем без проверок.
    *   `true`: фильтр включен, проверяется страна пользователя.
*   `allowedCountries` (array of strings): список разрешенных кодов стран в формате **ISO Alpha-2** (например, `["RU", "BY", "KZ"]`).
    *   **Важно**: Если список разрешенных стран пустой (`[]`), фильтр автоматически разрешает доступ всем пользователям во избежание случайных блокировок.
*   `unknownCountryPolicy` (string): определяет политику доступа в случае, если страну пользователя определить не удалось ни одним способом.
    *   `"allow"` (по умолчанию): разрешить доступ.
    *   `"deny"`: заблокировать доступ с кодом HTTP 403.
*   `logDeniedRequests` (boolean): включает логирование заблокированных обращений в консоль сервера.
    *   `true` (по умолчанию): логирует исходный IP подключения, прокси-IP, определенную страну и причину блокировки.
    *   `false`: отключает логирование заблокированных обращений.
*   `trustProxyHeaders` (boolean): определяет, следует ли доверять HTTP-заголовкам прокси-сервера (таким как `CF-Connecting-IP`, `X-Forwarded-For`, `CF-IPCountry`, `X-Country-Code`, `Cloudfront-Viewer-Country`, `X-AppEngine-Country`).
    *   `false` (**по умолчанию**): абсолютно игнорирует любые прокси-заголовки от клиента для предотвращения спуфинга (подмены заголовков). Местоположение будет определяться исключительно по IP физического сетевого подключения (`req.socket.remoteAddress`) через базу GeoIP.
    *   `true`: доверять прокси-заголовкам (только если соединение установлено из доверенного источника).
*   `trustedProxyIps` (array of strings): список разрешенных IP-адресов или сетевых подсетей в формате CIDR (например, `["10.0.0.1", "192.168.1.0/24"]`) прокси-серверов.
    *   **Защита от спуфинга**: Если `trustProxyHeaders` установлено в `true`, но `trustedProxyIps` пуст, в production-режиме прокси-заголовкам доверять **нельзя**. Соединение будет обрабатываться как прямое (untrusted proxy), и заголовки будут проигнорированы.

## 🚀 Инструкция: Как включить ограничение и добавить страны

Для активации гео-ограничений выполните следующие шаги:

1.  Откройте файл конфигурации `/config/access-control.json`.
2.  Установите флаг `"enabled": true`.
3.  Добавьте коды разрешенных стран в массив `"allowedCountries"`.
4.  Сохраните файл. Сервер автоматически перечитает конфигурацию при следующем запросе.

### Пример конфигурации для разрешения доступа только из Германии и США:
```json
{
  "geoAccess": {
    "enabled": true,
    "allowedCountries": ["DE", "US"],
    "unknownCountryPolicy": "allow",
    "logDeniedRequests": true,
    "trustProxyHeaders": false,
    "trustedProxyIps": []
  }
}
```

## 🔒 Защита от спуфинга (Header Spoofing Protection)

Если ваше приложение развернуто в облаке или за обратным прокси (Cloudflare, AWS CloudFront, Nginx и т.д.), злоумышленник может отправить поддельные HTTP-заголовки (например, `CF-IPCountry: US`), чтобы обойти гео-фильтрацию.

Для предотвращения этого в модуле реализован строгий механизм верификации источника:

1.  По умолчанию `trustProxyHeaders` равен `false`. Заголовки прокси полностью отбрасываются.
2.  При включении `"trustProxyHeaders": true`, вам обязательно нужно перечислить IP-адреса ваших балансировщиков или прокси-серверов в `"trustedProxyIps"`.
3.  Поддерживаются как одиночные IP-адреса, так и диапазоны сетей в формате **CIDR** (например, `192.168.1.0/24`).

### Пример безопасной конфигурации при работе через Cloudflare / Nginx (IP: 10.0.0.5):
```json
{
  "geoAccess": {
    "enabled": true,
    "allowedCountries": ["RU", "KZ"],
    "unknownCountryPolicy": "deny",
    "logDeniedRequests": true,
    "trustProxyHeaders": true,
    "trustedProxyIps": [
      "10.0.0.5",
      "172.16.0.0/12"
    ]
  }
}
```

Если запрос придет с IP `10.0.0.5` — модуль применит заголовок `CF-IPCountry`. Если запрос придет напрямую в обход прокси с IP `99.88.77.66` — заголовки прокси будут проигнорированы, IP определится как `99.88.77.66`, а страна будет вычислена только по базе данных GeoIP (или применится `unknownCountryPolicy`).

## 🔍 Алгоритм определения страны и IP

Сервер определяет геолокацию пользователя в два этапа:

### 1. Определение IP-адреса
*   Если прокси доверенный:
    1.  Заголовок `CF-Connecting-IP` (Cloudflare).
    2.  Первый IP в заголовке `X-Forwarded-For`.
*   Если прокси не доверен или `trustProxyHeaders` выключен:
    1.  Прямой физический IP-адрес подключения (`req.socket.remoteAddress`).

### 2. Определение страны (Country Lookup)
1.  **Заголовки прокси-серверов** (если прокси доверен):
    *   `CF-IPCountry`
    *   `X-Country-Code`
    *   `Cloudfront-Viewer-Country`
    *   `X-AppEngine-Country`
2.  **Локальная база GeoIP-lite** (всегда доступный fallback-источник):
    *   Поиск страны по вычисленному IP-адресу.
3.  **Политика `unknownCountryPolicy`**:
    *   Если определить страну не удалось ни одним способом, применяется заданная политика.

## 📦 Инструкция по использованию локальной GeoIP базы

Если ваше приложение развернуто на собственном сервере без внешних прокси-серверов, рекомендуется использовать локальную базу GeoIP:

1.  Установите пакет `geoip-lite` в зависимости вашего проекта:
    ```bash
    npm install geoip-lite
    ```
2.  База данных стран автоматически скачивается при установке в директорию библиотеки.
3.  Для регулярного обновления базы данных IP-адресов можно использовать утилиту обновления:
    ```bash
    node node_modules/geoip-lite/scripts/update-db.js
    ```
4.  Приложение защищено от отсутствия пакета или базы данных — при их отсутствии оно переходит в безопасный режим работы.

## 🔒 Безопасность и Совместимость
*   **Сохранение паролей**: Гео-ограничение работает как дополнительный сетевой фильтр (до авторизации). Парольная защита (`verifyPassword` в `server.ts`) продолжает работать независимо в штатном режиме.
*   **Исключение критических падений**: Модуль устойчив к отсутствию папок, файлов или зависимостей. При любых ошибках чтения он безопасно переходит в режим "разрешить всем".
*   **Ресурсы и статика**: Гео-фильтр проверяет запросы ко всем ресурсам (включая статику и экспорт PDF). Разрешенные пользователи имеют полноценный доступ ко всему функционалу.

# 🛡️ Модель расширенного доступа к защищенным функциям (Advanced Access Model)

Данный модуль предоставляет механизм централизованной защиты для критических или деструктивных операций (таких как изменение даты оценки, экспорт отчетов, принудительная синхронизация данных и т.д.) через **один общий универсальный код / пароль расширенных функций** для всего приложения.

Обычный просмотр дашборда и стандартный функционал остаются доступными всем авторизованным пользователям в штатном режиме.

---

## 🛠️ Файл конфигурации (`config/access-control.json`)

Параметры расширенного доступа хранятся в том же конфигурационном файле под ключом `"advancedAccess"`:

```json
{
  "advancedAccess": {
    "enabled": false,
    "displayName": "Код расширенного доступа",
    "passwordHash": "",
    "ttlMinutes": 60,
    "protectedActions": [
      "assessmentDateChange",
      "syncData",
      "exportData",
      "exportPdf",
      "exportProjectCard",
      "exportProjectCardPdf"
    ]
  }
}
```

### Описание параметров:
*   `enabled` (boolean): включает или выключает проверку кода расширенного доступа.
    *   `false` (**по умолчанию**): защищенные функции выполняются мгновенно без запроса пароля.
    *   `true`: при активации любого из защищенных действий у пользователя запрашивается код расширенного доступа.
*   `displayName` (string): человекочитаемое наименование кода для отображения в интерфейсе модального окна и логах. По умолчанию: `"Код расширенного доступа"`.
*   `passwordHash` (string): SHA-256 хэш общего пароля расширенных функций (например, хэш от `"my-password"`).
*   `ttlMinutes` (number): время действия подтвержденного доступа в минутах (таймаут сессии расширенного доступа). В течение этого времени пользователю не придется вводить код повторно при совершении других защищенных действий. По умолчанию: `60`.
*   `protectedActions` (array of strings): список идентификаторов действий, которые требуют ввода кода расширенного доступа:
    *   `assessmentDateChange` — Изменение/применение даты оценки.
    *   `syncData` — Принудительная ручная синхронизация данных с Google Sheets.
    *   `exportData` — Экспорт данных портфеля (Excel).
    *   `exportPdf` — Формирование общего PDF-отчета портфеля.
    *   `exportProjectCard` / `exportProjectCardPdf` — Экспорт карточки проекта / формирование PDF карточки проекта.

## 🛡️ Безопасность и хранение секретов

Для обеспечения безопасности и предотвращения утечек:
1.  **Запрещено хранить реальный пароль в коде или в репозитории**.
2.  Вы можете задать пароль через окружение, используя переменные среды:
    *   `ADVANCED_ACCESS_PASSWORD_HASH` — SHA-256 хэш кода расширенного доступа (рекомендуется для production).
    *   `ADVANCED_ACCESS_PASSWORD` — текстовый (plain) пароль (удобно для локальной разработки).
3.  Если переменные окружения не заданы, сервер использует `passwordHash` из файла `config/access-control.json`.
4.  При изменении файла конфигурации `config/access-control.json` правила обновляются "на лету" без перезапуска. Однако изменение переменных окружения (таких как `ADVANCED_ACCESS_PASSWORD` или `ADVANCED_ACCESS_PASSWORD_HASH`) обычно требует перезапуска процесса сервера или redeploy (переразвертывания) приложения, если среда выполнения не поддерживает динамическое обновление переменных на лету.

### 🧪 Пример временной настройки для тестирования:
Для локального тестирования или быстрой проверки можно временно задать текстовый пароль в файле `.env` или в переменных среды:
```env
ADVANCED_ACCESS_PASSWORD=321
```
**⚠️ ВНИМАНИЕ**: Значение `321` предназначено исключительно для временной локальной проверки или отладки и ни в коем случае не должно использоваться в рабочей (production) среде. Для промышленной эксплуатации обязательно используйте длинный криптостойкий пароль и задавайте его в виде хэша `ADVANCED_ACCESS_PASSWORD_HASH`.

## 🔒 Серверная защита сессий (Server-Authoritative Sessions)

Для обеспечения максимальной безопасности:
1. **Сессия на основе cookies**: После верного ввода кода сервер генерирует криптографически стойкий токен сессии и сохраняет его в защищенной `HttpOnly` куке `advanced_access_session`.
2. **Отсутствие хранения на клиенте**: Локальное хранилище `localStorage` используется исключительно для оптимизации UX (например, быстрое сокрытие кнопок или превентивная подсказка), но главным источником истины всегда является проверка статуса сессии на сервере (`GET /api/advanced-access/status`) и валидация запросов.
3. **Защита API на бэкенде**:
   - `GET /api/projects?sync=true` возвращает статус **403 Forbidden** в случае отсутствия активной сессии расширенного доступа.
   - Любой запрос к `GET /api/projects` с произвольной датой (`assessmentDate` отличной от сегодняшней даты) возвращает **403 Forbidden** без активного расширенного доступа. Это защищает систему от несанкционированного изменения аналитического контура.
   - При получении 403 от API из-за истекшей сессии приложении безопасно и бесшовно сбрасывает выбранную дату на `'today'` (Сегодня) во избежание сбоя отображения дашборда для обычных пользователей.
